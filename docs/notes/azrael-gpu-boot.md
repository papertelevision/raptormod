Josh (2026-10-07): the GPU version must load before the game and show its own boot; the CPU/8-bit boot stays for a future "retro" option (watcher -Retro / -NoBootHd).

**Why the 8-bit boot still showed:** the watcher attached ~18 s after DOSBox appeared (Get-AztGuestBase scanned the whole process 4x) and only ShowGuestFrame'd the boot after room detection — the last ~3 s.

**How it works now**
- Build-AztMod writes `art\boot-hd.json` (texts, beats in us, effect tables, px sizes, ink INDICES, scale/designW) right after `$BOOT_DUMP_FREEZE`. Changing the boot constants = rebuild (manifest stays identical; verified by hash).
- `BootHd.cs` (own thread, ~60 fps, <1 ms/frame at 2310x1386) reads aztBootState/T0/El (+0/+12/+16, contiguous) and aztReboot; carries guest el forward between guest frames; random beats keyed to a 24 Hz tick hash. Inks resolved via the live palette (tcPal32). Type drawn at the DESIGNED size (Zoom 1.116 = the 8-bit cap was BSS only).
- At the shutter beat (15.5 s) it HOLDS and winds the guest boot to its end (writes T0) so takeover starts; Step-TrueColour 'run' calls Reveal(); then Overlay.Decorate draws shutter panels/lips/ghost + calibration over the host 3D for 1.4 s. HoldMaxMs 10 s fallback.
- Watcher supervisor: attach → Initialize-TrueColour → Start-BootHd → THEN wait for staging buffer (unbounded) → HostView. Set-Engine3D false skips ov.Hide() while BootHd.Covering (reload re-boot).
- Get-AztGuestBase -MinRegion 8MB (guest RAM is one 32 MB block) + requires needles from BOTH objects (file copies fool single-object matches); watcher falls back to full scan / -AllowOneObject after 20 s.
- Play-HostRender.cmd now runs the watcher with `-Once -Launch -GameDir`; the watcher loads the room index, then Start-Process's DOSBox.
